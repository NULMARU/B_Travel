# B_Travel 웹앱 — 개발계획 v0.2

> v0.1 은 "무엇을 만들 것인가"의 설계도였다.
> v0.2 는 **"모호한 원취지를 어떻게 구체 코드로 내리는가"** 의 실행 기록이다.
> 이 문서의 모든 항목은 이 커밋 시점에 실제로 구현되어 있다.

## 1. 원취지의 재해석

v0.1 의 컨셉 한 줄 — *"현장 음성 → 본문(서사) + 사실레이어(GEO) → 다국어 발행 → 라이딩 중 듣기"* —
을 다시 읽으면, 이 프로젝트의 본질은 앱이 아니라 **사이클(순환)** 이다.

```
        ┌────────────────────────────────────────────┐
        │                                            │
   1.계획 → 2.현장 → 3.본문 → 4.사실레이어 → 5.번역 → 6.듣기
        │   (모바일)   (데스크탑)              (발행)    (모바일)
        └──── 6단계의 출력(어제 본문 듣기)이 다음 라이딩의 입력이 됨
```

여기서 도출한 세 가지 구현 원칙:

1. **한 라이딩 = 한 폴더 = 한 화면.** 라이딩 상세 화면 하나에서 6단계가 전부 보여야 한다.
   단계를 페이지로 쪼개면 사이클이 끊긴다. → 상세 화면을 단계별 탭(현장/GPX/본문/사실/번역/듣기)으로 구성.
2. **웹앱은 AI 를 호출하지 않는다. 대신 AI 에게 넘길 짐을 싼다.** 3·4·5단계의 버튼은
   전부 "컨텍스트+프롬프트 한 묶음 클립보드 복사"다. LLM 비용·키·환각 책임을 앱에 안 끌어들인다.
3. **디바이스가 안 되는 건 억지로 되게 하지 않는다.** iOS Safari 에 폴더 쓰기를 강요하지 않고,
   각 디바이스가 잘하는 것만 시킨다 (아래 §4).

### 2.1 왜 지도를 MapLibre 가 아니라 SVG 로 그렸나

v0.1 은 MapLibre GL + OSM 타일을 계획했다. 이번에 의도적으로 내렸다:

- MapLibre GL 은 gzip 후에도 ~230KB + 타일은 네트워크 필수 → **오프라인 PWA 원칙과 충돌**.
- 이 앱에서 지도의 역할은 내비게이션이 아니라 "**경로의 형태와 고도를 한눈에**"다.
  트랙 폴리라인 + 시작/끝/최고점 마커 + 고도 프로필이면 충분하고, 이건 GPX 포인트만으로
  의존성 0, 오프라인 100% 로 그릴 수 있다.
- 실제 지형 위 확인이 필요하면 각 좌표에 OSM 외부 링크를 달아두는 것으로 족하다.

MapLibre 는 "타일 위 사진 핀 자동 배치"가 필요해지는 시점(v0.3, 사진 EXIF 매칭)에 다시 검토.

### 2.2 현장 캡처의 "포켓 모드" — 리스크 7.1 의 답

v0.1 리스크 7.1(iOS PWA 제약)의 옵션 B 를 구체화했다. 핵심 발견:
**`showDirectoryPicker` 는 데스크탑 Chromium 전용이다. 안드로이드 크롬도 안 된다.**
즉 "모바일에서 vault 폴더에 직접 쓰기"는 어떤 폰에서도 불가능하다. 그래서:

```
현장(폰, 아무 브라우저) ──음성·위치──▶ 포켓(IndexedDB, 디바이스 로컬)
                                        │  "내보내기" = ① 전체 텍스트 복사
                                        │              ② field-notes 조각 .md 다운로드
                                        ▼
집(데스크탑 Chromium) ──붙여넣기/파일 이동──▶ vault/rides/…/field-notes.md
```

- 폰에서는 어차피 Obsidian Git / 파일 앱 / 메신저 등 "텍스트를 옮길 길"이 여럿이다.
  포켓 모드는 **저장을 책임지고, 이동은 사용자의 기존 습관에 맡긴다.**
- 데스크탑에서 같은 탭을 열면 vault 에 **직접** append 된다 (포켓 불필요).
- 사진은 폰 카메라롤에 이미 있으므로 앱이 다시 보관하지 않는다. 데스크탑에서
  `photos/` 로 옮기는 흐름 유지 (v0.3 에서 EXIF 핀 매칭 추가 시 재검토).

## 3. CLI 핸드오프 프롬프트 규격

3·4·5단계 버튼이 클립보드에 싣는 묶음의 공통 구조:

```
[역할 선언 + 출력 파일 경로 + 완료 조건]   ← docs/04_사실레이어_프롬프트.md 등 기존 프롬프트
---
[컨텍스트 1: gpx_facts.yaml 내용]
[컨텍스트 2: field-notes.md 또는 index.md 내용]
```

사용자는 vault 폴더에서 `claude` 를 열고 붙여넣기만 하면 된다. 결과 파일이 vault 에
저장되면 웹앱의 "새로고침"이 감지한다. (파일 watch 는 Chromium 의
FileSystemObserver 가 안정화되면 v0.3 에서 자동화.)

## 4. 검토 요청 사항 ①: "GitHub 레포 저장 + 스마트폰으로 보기"가 좋은가

**결론: 좋다. 단, 역할을 나눠야 한다.** 검토 과정에서 발견한 사실: 이전 커밋들에
GitHub Pages 배포 워크플로가 이미 있었지만 **원격 레포 자체가 생성된 적이 없어서
한 번도 배포되지 않은 상태**였다. 이번에 실제로 생성·배포했다.

| 층 | 무엇을 | 어디에 | 왜 |
| --- | --- | --- | --- |
| 앱 (이 레포) | 웹앱 코드 + 데모 vault | `NULMARU/B_Travel` public + GitHub Pages | 무료 CDN, PWA 설치 가능, 폰에서 URL 하나로 접근 |
| 데이터 (사용자별) | 각자의 cre-vault | 각자의 private repo (Obsidian Git 등) | 여행기는 사적 데이터. 앱 레포에 섞이면 안 됨 |
| 발행물 (공개) | `geo-fact*.md` 만 | 추후 `_publish/` → 별도 Pages (v0.3) | GEO 목적상 공개 필요한 것만 공개 |

스마트폰에서의 실제 사용 그림:

- **모든 폰 (iOS 포함)**: PWA 설치 → 데모 모드로 화면 전체 탐색, 현장 탭에서 포켓 모드 음성 메모, 듣기 탭 재생.
- **안드로이드 크롬**: 위와 동일 (폴더 쓰기는 폰에서 원래 불가 — §2.2).
- **데스크탑 Chromium**: 풀 기능 (vault 직접 읽기·쓰기).

주의점 한 가지: 레포가 public 이므로 **사용자 vault 를 절대 이 레포 안에 두지 말 것**
(`.gitignore` 에 `/rides/`, `/_publish/` 방어 이미 있음). sample-vault 는 공개용으로 만든
가상 데이터만 담는다.
