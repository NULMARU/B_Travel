# B_Travel v0.3 — 세 순간, 세 버튼

## 1. v0.2 의 문제 진단

v0.2 는 6단계 파이프라인을 **화면에 그대로 노출**했다. 탭 7개, 매번 vault 재선택,
CLI 핸드오프 3회 반복, 새 라이딩 폼. 기능은 완성됐지만 "열 때마다 생각해야 하는 앱"이었다.

## 2. v0.3 원칙

> **파이프라인은 코드가 들고, 사용자에겐 버튼 하나만.**

사용자가 이 도구를 만나는 순간은 셋뿐이다:

| 순간 | 디바이스 | 화면 | 버튼 |
| --- | --- | --- | --- |
| A. 라이딩 중 | 폰 | `/capture` | 🎙 탭하고 말하기 (오늘 폴더 자동) |
| B. 집에 와서 | 데스크탑 | 홈 = 다음 할 일 카드 | 상태 머신이 계산한 액션 1개 |
| C. 다음 출발 전 | 폰 | `/listen` | ▶ 재생 |

## 3. 구현 내역

### 3.1 vault 연계 — 디바이스별 최적 경로 (자동 선택)

```
데스크탑 Chromium ──(File System Access, 핸들 IndexedDB 영속화)──▶ vault 폴더 직접
폰 (모든 브라우저) ──(GitHub contents API + fine-grained PAT)──▶ vault repo
오프라인/미설정   ──(IndexedDB 포켓, 절대 유실 없음)──▶ 나중에 전송
```

- **핸들 영속화** (`persist.ts`): 한 번 선택하면 재방문 시 자동 연결.
  권한이 만료되면 "🔓 다시 연결" 버튼 하나 (브라우저 보안상 클릭 1회는 불가피).
- **GitHub 동기화** (`github.ts`): 폰의 음성 메모가 `rides/<오늘>/field-notes.md` 에
  바로 append 되고 (409 재시도 포함), 듣기는 repo 의 `index.md` 를 바로 읽는다.
  토큰은 localStorage 에만 저장 (Contents 권한만 가진 fine-grained PAT 안내 포함).
  데스크탑 vault 와는 Obsidian Git 등 기존 동기화가 잇는다 — v0.1 §3.1 의
  "동기화 허브 = GitHub repo" 를 그대로 구현한 것.
- **저장 우선순위** (`/capture`): vault 직접 > GitHub > 포켓. 온라인 저장 실패 시
  포켓 폴백 — 현장 기록은 어떤 경우에도 유실되지 않는다.

### 3.2 CLI 오케스트레이션의 이양 — /ride-finish 스킬

v0.2 의 "프롬프트+컨텍스트 묶음 복사" 3종을 폐기했다. Claude Code 는 vault 폴더를
직접 읽을 수 있으므로 앱이 컨텍스트를 나를 이유가 없다.

- 앱이 vault 에 `.claude/skills/ride-finish/SKILL.md` + `CLAUDE.md` 를 **설치**해준다
  (`skillkit.ts`, 설정 또는 홈에서 1클릭. 기존 CLAUDE.md 는 건드리지 않음).
- 이후 앱의 모든 CLI 버튼은 한 줄 복사: `claude "/ride-finish 2026-07-18_한강"`.
  스킬이 본문 → 사실레이어(린터 규칙 자체 검수) → 요청 시 번역 → meta.yaml 갱신까지
  한 대화로 처리한다.

### 3.3 다음 할 일 엔진 (`nextstep.ts`)

meta.yaml workflow / 파일 존재 여부 → 단 하나의 액션:
현장 메모 없음 → "🎙 기록" / GPX 없음 → "📈 GPX 올리기" / 사실레이어 없음 →
"📋 정리 명령 복사" / 린터 미통과 → "🔍 검수" / 완료 → "🎧 듣기".
데스크탑 홈은 이 버튼 하나가 화면의 중심이다.

### 3.4 모바일 최적화

- 하단 탭바 (홈/기록/듣기/라이딩/설정), safe-area 대응, 16px 입력(iOS 줌 방지),
  탭 타깃 확대.
- 폰 홈 = 큰 카드 2개 (기록/듣기). 6단계 탭 화면은 "라이딩 → 자세히 보기"로 강등.
- 새 라이딩 폼은 경로에서 제거 — 첫 기록이 오늘 폴더를 자동 생성한다
  (폼은 `/rides/new` 에 존치, 데스크탑 보조용).

## 4. 사용 시나리오 (베타 온보딩 그대로)

1. **폰 최초 1회**: 설정 → vault repo(owner/repo) + PAT 입력 → 연결 테스트.
   홈에 앱 설치(PWA).
2. **데스크탑 최초 1회**: 홈 → vault 폴더 선택 → 스킬 설치 1클릭.
3. **이후 매 라이딩**: 폰 🎙 (자동 저장) → 집에서 git pull 후 홈의 버튼 1개
   (GPX 올리기 → 명령 복사 → 터미널 붙여넣기) → 다음 출발 전 폰 ▶.

## 5. 의도적으로 안 한 것

- GitHub OAuth 웹 플로 — 서버 없는 정적 앱에서는 PAT 가 가장 정직한 방법.
  베타 인원(5~20명)에게는 설정 가이드로 충분. SaaS 화 시점에 재검토.
- 폰에서의 사진 업로드 — 카메라롤+EXIF 매칭은 v0.4 후보 유지.
- 오프라인 GPS 트랙 기록 — v0.1 §7.2 결정 유지 (Strava 등 기존 앱의 GPX export).
